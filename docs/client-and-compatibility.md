# 客户端与兼容性

[返回文档目录](README.md)

本页只描述服务端开发和本地联调需要了解的 v079 客户端兼容信息。客户端程序、HShield 替换文件和其他第三方二进制不属于 Maven 构建产物，也没有包含在本仓库中。

## 协议版本

服务端常量定义的 MapleStory 协议版本为 79。联调客户端必须匹配该协议及项目使用的区域类型、Opcode 和加密行为。

出现以下情况时，不要先假定是数据库问题：

- 客户端一连接就断开；
- 服务端记录未知 Opcode；
- 登录成功后切换频道失败；
- 数据包长度、字符编码或加密校验异常；
- 使用其他补丁级别客户端时界面正常但操作无响应。

这类问题可能来自客户端版本、登录器参数、`sendops.properties`、`recvops.properties` 或协议实现不一致。

## 仓库中的客户端辅助脚本

### `V079登录器.bat`

该批处理在当前目录调用：

```text
ms079-launch-guard.ps1
```

它本身不包含客户端，也不下载客户端文件。使用时通常需要把相关 BAT 和 PowerShell 脚本放在包含 `MapleStory079.exe` 的客户端目录中。

### `ms079-launch-guard.ps1`

守护脚本的主要行为包括：

- 检查 `MapleStory079.exe` 是否存在；
- 清理残留的 MapleStory 客户端进程；
- 等待本机登录、频道和商城端口就绪；
- 设置 Windows 应用兼容层；
- 处理部分旧客户端路径和显示模式问题；
- 启动客户端并传入 `127.0.0.1`、`9595`；
- 注册 `Ctrl+Shift+F12` 紧急停止快捷键；
- 客户端持续无响应达到 150 秒后强制停止；
- 强制停止时恢复显示模式。

仓库还存在 `V079启动与守护.ps1`；当前它与 `ms079-launch-guard.ps1` 内容完全相同，但 `V079登录器.bat` 实际调用的是后者。维护时应先决定是否继续保留两个副本，并避免只修改其中一个造成行为分叉。

### `V079紧急停止.bat`

该脚本使用 `-StopOnly` 调用守护脚本，用于终止已知 MapleStory 进程并恢复显示模式。它会强制结束匹配的客户端进程，运行前应确认没有其他同名客户端实例需要保留。

## 服务端就绪检查

守护脚本默认等待：

```text
9595
7576
7577
7578
8600
```

每个端口连接检查最多等待约 750 毫秒；一轮检查后如果仍有端口关闭，脚本等待 3 秒再重试，整体截止时间为 4 分钟。这与默认三频道配置一致。如果修改了频道基础端口或频道数量，客户端守护脚本中的检查列表不会自动读取 `服务端配置.ini`，需要同步评估和调整，否则可能出现服务端已经启动、守护脚本仍持续等待的情况。

## 客户端路径兼容

守护脚本默认寻找：

```text
MapleStory079.exe
```

部分历史 HShield 环境会在 `HShield\ehsvc.ini` 中记录期望启动路径。守护脚本会读取其中的 `GamePath`，当该路径真实存在时按其指定路径启动，以兼容旧客户端对路径拼写或联接目录的依赖。

不要把本机绝对客户端路径、用户名目录或第三方下载目录写回仓库脚本。

## `downloadinfo.dat`

守护脚本检测客户端目录中的 `downloadinfo.dat`。如果该文件存在但没有隐藏属性，脚本会将其设为隐藏，以规避旧客户端在更新标记文件上持续读取而不进入登录连接的问题。

这属于特定旧客户端行为的兼容处理。若使用不同来源或补丁级别的客户端，应通过实际进程、文件访问和网络连接验证，不要假定所有客户端都需要同样处理。

## Windows 显示和紧急退出

守护脚本会写入当前用户的 Windows 应用兼容性注册表项，并设置进程级 `__COMPAT_LAYER`。这可能影响旧版全屏、16 位色彩和高 DPI 行为。

客户端启动后：

- `Ctrl+Shift+F12` 用于紧急停止；
- 守护脚本持续监视客户端响应状态；
- 强制停止后尝试恢复系统显示模式；
- 也可以执行 `V079紧急停止.bat`。

这些操作会结束进程并修改当前用户的兼容性设置。排障时应记录客户端路径、Windows 版本、兼容层和显示模式，而不是反复强制终止后忽略环境变化。

## 本地连接

当前登录器把客户端连接目标设为：

```text
127.0.0.1:9595
```

因此默认流程只适用于客户端和服务端在同一台 Windows 主机，或端口通过本机转发到服务端的环境。

局域网联调需要同时评估：

- `服务端配置.ini` 中的 `server.address`；
- 登录器实际传入的目标地址；
- 登录、频道和商城端口；
- Windows 防火墙或容器端口发布；
- 客户端是否能够访问服务端返回的频道地址。

只替换一个 `127.0.0.1` 不一定足够。登录服务可达但频道切换失败，通常说明服务端返回地址或频道端口仍不可达。

## 客户端资源

原 README 中的 v079 客户端短链已保留在[外部资源](external-resources.md)。使用前应注意：

- 确认协议版本为 v079；
- 不要把客户端二进制提交进服务端仓库；
- 不要在含真实账号或敏感文件的日常系统上直接运行未知二进制；
- 优先记录文件哈希、来源和获取日期；
- 客户端行为异常时提供哈希和版本信息，比只提供文件名更有诊断价值。

## 联调前检查清单

- 服务端日志已经出现启动完成；
- MySQL、登录、频道和商城服务均正常；
- 客户端协议版本匹配；
- 登录器连接地址正确；
- `server.address` 对客户端可达；
- 频道数和守护脚本等待端口一致；
- 没有残留的旧客户端进程；
- Windows 显示兼容设置符合当前客户端；
- 账号和密码仅用于隔离测试，未与任何真实系统复用；
- 已限制 `日志/logs/ACPW.txt` 等遗留明文登录日志的访问；
- 第三方资源已自行完成来源和安全检查。
