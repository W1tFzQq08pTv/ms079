# 常见问题

[返回文档目录](README.md)

排障时先记录预期行为、实际输入、实际日志和失败阶段。不要只根据客户端表象判断服务端根因。

## Maven 使用了错误的 Java

### 表现

- 编译提示不支持的 class 版本；
- JavaScript 数据校验找不到 JavaScript 引擎；
- IDE 能编译但终端失败，或相反。

### 检查

```bash
java -version
./mvnw -version
```

同时检查 IDE 的 Project SDK 和 Maven Runner。当前基线是 Java 8；更高版本 JDK 可能移除或改变项目依赖的 JavaScript 引擎。

## Maven Wrapper 无法下载

### 表现

- 首次执行 `mvnw` 时超时；
- 无法访问 Maven Central；
- Maven 发行包 SHA-256 校验失败。

### 处理

- 检查 DNS、代理和 TLS；
- 检查 `.mvn/wrapper/maven-wrapper.properties` 的发行地址；
- 不要删除或跳过 SHA-256 校验来绕过来源异常；
- 企业网络可按 Maven Wrapper 官方方式配置受信任仓库镜像。

## 找不到 `服务端配置.ini`

### 原因

程序固定按当前工作目录读取该文件。

### 处理

- IDE Working directory 设置为仓库根目录；
- 分发包中从解压根目录启动；
- Docker 确认挂载目标是 `/app/服务端配置.ini`；
- 检查中文文件名是否被解压工具改名。

## 数据库连接失败

### 检查顺序

1. MySQL 5.7 进程或容器是否运行；
2. `ms079` schema 是否存在；
3. `db/ms079.sql` 是否完整导入；
4. JDBC 地址、端口、账号和密码是否匹配；
5. 数据库用户是否允许来自当前运行环境的连接；
6. 字符集、时区和 SSL 参数是否符合环境；
7. Docker 方式是否真的共享 `ms079-mysql` 网络命名空间。

不要在问题报告、日志截图或命令输出中暴露数据库密码。

## 数据库存在但缺表

只创建空 schema 不足以启动服务端。检查：

```sql
SELECT COUNT(*)
FROM information_schema.tables
WHERE table_schema = 'ms079';
```

如果 SQL 导入中途报错，应从第一条错误开始解决。不要手工创建一个报错表后继续，因为后续基础数据、索引和其他表可能也未导入。

不要为了“补齐缺表”直接对已有业务库重新运行整个 `db/ms079.sql`。该文件会删除并重建同名表、覆盖数据，不是增量修复脚本。应先恢复到备份或在新空 schema 中重新导入，再针对需要保留的数据设计迁移。

## 导入后出现陌生账号、角色或业务数据

`db/ms079.sql` 是历史完整数据转储，不是空 schema，包含示例管理员账号、角色、背包、任务、掉落和其他初始记录。出现这些数据不表示导入串库。共享或对外环境必须先审查并清理预置账号、角色、MAC、地址和其他不需要的数据，不能沿用转储中的身份信息。

## 找不到 WZ 目录

源码默认读取工作目录下的 `wz`，可通过以下系统属性覆盖：

```text
-Dwz.path=/实际路径/wz
```

检查：

- 属性名必须是 `wz.path`；
- 目标目录下应直接包含 `Character.wz`、`Item.wz`、`Map.wz` 等目录；
- 运行用户具有读取权限；
- Docker 中 `/app/wz` 挂载成功；
- 工作目录没有偏离仓库根目录。

## JavaScript 引擎不可用

仓库脚本和数据校验依赖 Java 8 JavaScript 引擎。如果使用现代 JDK，可能出现引擎为 `null` 或不支持编译。

处理方式是先切回项目基线 JDK 8 验证，不要在未评估全部脚本兼容性的情况下临时更换脚本引擎。

## 脚本语法校验通过但运行失败

语法编译不会检查：

- Java 方法是否存在；
- 注入对象是否支持目标调用；
- NPC、地图、任务或道具 ID 是否正确；
- 数据库记录是否存在；
- 特定玩家状态是否满足。

应使用隔离测试角色走实际分支，并结合服务端异常堆栈定位。

## WZ XML 可以解析但游戏行为错误

XML 可解析只证明格式基本有效。继续检查：

- 数据节点路径和 ID；
- 同名节点及顺序；
- Java 工厂读取的是哪个 WZ 目录；
- 数据是否已经缓存；
- 是否需要完整重启；
- String、Item、Map、Mob 等跨文件引用是否一致。

## 服务端进程存在但端口未监听

服务端可能仍在加载大量 WZ 数据，或者已经在初始化阶段失败但 Java 进程暂未退出。

检查完整日志并查找端口绑定错误。即使出现“服务端启动完毕”，登录或频道绑定失败也可能只记录异常而没有终止整个 Java 进程。继续检查：

- `9595` 登录；
- `server.channel.port + 频道编号`；
- `8600` 商城；
- 端口是否已被其他进程占用。

如果 `server.channel.count` 大于 10，当前运行时仍只启动前 10 个频道；后续频道端口不监听并不是启动等待不足。配置校验允许更大的值，但与运行时上限不一致。

## Docker 报找不到 `ms079-mysql`

当前 Compose 使用：

```text
network_mode: container:ms079-mysql
```

必须提前存在这个精确名称的运行中容器。仅安装 MySQL 到宿主机，或创建另一个名称的 MySQL 容器，都不能满足该配置。

## Docker 容器运行但宿主机无法连接游戏端口

因为服务端共享数据库容器的网络命名空间，端口必须在创建 `ms079-mysql` 时发布。不能通过给 `ms079-server` 增加普通 `ports` 来修复当前结构。

检查数据库容器的实际端口映射、服务端日志和容器网络，不要只看 `compose.yaml`。

## Apple Silicon 上 MySQL 5.7 无法启动

旧 MySQL 5.7 镜像可能没有原生 ARM64 变体。开发环境可评估 `--platform linux/amd64`，但会引入模拟和性能差异。应记录主机架构、镜像摘要和容器日志。

## 客户端无法连接

按顺序检查：

1. 登录端口是否监听；
2. 登录器是否连接正确地址和 `9595`；
3. `server.address` 是否对客户端可达；
4. 默认频道端口是否监听和可达；
5. 商城端口是否可达；
6. 客户端是否真的是协议 v079；
7. Opcode、补丁级别和加密行为是否匹配；
8. 服务端是否记录连接或解码异常。

“登录界面打不开”“登录后掉线”“切频道失败”对应的网络阶段不同，应分别判断。

## 客户端黑屏、显示异常或无法退出

- 使用 `Ctrl+Shift+F12` 触发守护脚本紧急停止；
- 或运行 `V079紧急停止.bat`；
- 检查客户端实际启动路径；
- 检查 Windows 兼容层和显示模式；
- 检查 `downloadinfo.dat` 属性；
- 保留守护脚本输出；
- 不要连续启动多个客户端实例掩盖首个错误。

## 日志目录、丢失和敏感信息

本地 Shell 脚本会尝试创建 `logs`，Docker 也将宿主机 `./logs` 挂载为可写目录。检查运行用户是否有权限创建和写入，而不是直接使用管理员权限运行整个服务端。

项目还有遗留的 `日志/logs/` 路径。Docker Compose 没有挂载该目录，因此删除并重建容器后，其中的文件可能消失；不要把容器可写层当作持久日志存储。

当前成功登录流程会向 `日志/logs/ACPW.txt` 写入账号、明文密码、MAC 和地址。这不是普通脱敏即可公开分享的日志：

- 只能使用隔离、可丢弃且不复用的测试密码；
- 严格限制日志目录访问；
- 不要上传整个 `日志/`；
- 真实部署前先修复明文记录行为；
- 已经使用过的真实或复用密码必须轮换。

其他日志也可能包含账号、角色、地址和完整数据包。分享时只截取解决问题必需的最小片段，并逐字段脱敏。

## 自动注册显示开启但没有创建账号

当前实现存在两个没有同步的开关：配置属性 `server.register.auto` 和静态字段 `AutoRegister.autoRegister`。启动日志只反映前者，而创建账号分支还要求后者为 `true`；GM 切换命令也没有更新 `AutoRegister.autoRegister`。因此配置显示开启但无法注册属于当前代码限制，不应通过直接改数据库权限或暴露预置管理员账号来绕过。

需要可靠自动注册时应先修复开关状态来源、增加测试，并审查账号数量、MAC 限制、密码哈希和日志行为。当前自动注册使用无盐 SHA-1，部分旧密码兼容路径也会迁移到无盐 SHA-1，不能将其当作现代安全密码存储方案。

## assembly 分发包中的 BAT 无法启动

当前 release descriptor 会打入根目录 BAT，却不会打入 `compose.yaml` 或 `Dockerfile`。两个服务端 BAT 都调用 Docker Compose，所以仅解压 `ms079-*-dist.zip` 后运行 BAT 会因缺少 Compose 项目文件而失败。

这不是 Maven 依赖下载问题。应先选择明确的分发策略：要么把必要 Docker 文件加入归档并验证，要么使用与 `ms079.jar`、`lib/` 相匹配的原生 Java 启动脚本。当前 CI 不验证 assembly 归档的独立启动。

## 提交 Issue 前收集信息

- 操作系统和 CPU 架构；
- `java -version`；
- `./mvnw -version`；
- MySQL 版本；
- Docker 和 Compose 版本（如果使用）；
- 当前分支和提交 SHA；
- 本地 Java 或 Docker 启动方式；
- 最小复现步骤；
- 首条相关异常及必要上下文；
- 预期行为和实际行为；
- 是否修改过配置、SQL、WZ 或脚本；
- 客户端文件哈希和来源（客户端问题）。

安全漏洞、凭据泄露或可利用的越权问题请按 [`SECURITY.md`](../SECURITY.md) 私密报告，不要公开附上可直接利用的完整细节。
